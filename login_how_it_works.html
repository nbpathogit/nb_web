NB Patho — How login.php Works

Technical documentation for the authentication and session management flow in C:\anuchit2\nb_web\dev3\login.php

1. Related Files & Dependencies

login.php handles both rendering the login form (GET) and authenticating user credentials (POST). It relies on the following core files:

login.php Main login controller and HTML form view.
includes/init.php Registers the class autoloader (classes/*.php) and starts the PHP session (session_start()).
includes/db.php Creates and returns the PDO database connection ($conn).
classes/Auth.php Manages session state, 20-minute timeout, user group permissions, and login/logout audit logging.
classes/User.php Queries the user table, checks active status, and verifies password hashes.
classes/Url.php Builds subfolder-aware redirect URLs (Url::redirect()).

2. High-Level Authentication Flow

1. Request Arrives at login.php
Loads includes/init.php → starts session & detects deployment $subfolder from $_SERVER['PHP_SELF'].
2. Check Auth::isLoggedIn()
If the session already has a logged-in user → immediately redirects to /patient.php.
3. If POST Request (Form Submitted)
Connects to the database via require 'includes/db.php'.
4. Check User::isUserNameActive($conn, $username)
Queries SELECT * FROM user WHERE username = :username and checks user_status == 1.
If false → shows error: "Not found username or username is in active".
5. Check User::authenticate($conn, $username, $password)
Uses PHP password_verify($password, $user->password).
If false → shows error: "Passward is incorrect,Please try again" and preserves page_name, page_id, and subfolder.
6. Call Auth::login($conn, $username, $subfolder)
Regenerates session ID, stores User & Ugroup objects in $_SESSION, sets 20-minute timeout timer, and writes a "login" entry to the audit log via Log::add().
7. Post-Login Redirect
• If password is still "changeme" → redirects to /user_change_password.php.
• Else if $_POST['page_name'] is set → redirects to /{page_name}?id={page_id}.
• Otherwise → redirects to /patient.php.

3. Step-by-Step Code Breakdown

Step 1 Initialization & Subfolder Detection (Lines 1–15)

login.php first loads includes/init.php and extracts the application subfolder name (e.g., dev2 or dev3) from $_SERVER['PHP_SELF'] so redirects stay inside the right subfolder:

require 'includes/init.php';

$subfolder = str_replace("/","",$_SERVER['PHP_SELF']);
$subfolder = str_replace("login.php","",$subfolder);

// replace file name itself
$pieces = explode("/", $_SERVER['PHP_SELF']);
$subfolder = str_replace($pieces[sizeof($pieces)-1],"",$subfolder);

Step 2 Redirect Already-Authenticated Users (Lines 16–18)

If the user already has a valid session, they skip the login screen and go straight to /patient.php:

if (Auth::isLoggedIn()) {
    Url::redirect("/patient.php");
}

Step 3 Verify Active Status & Password on POST (Lines 20–28)

When the form is submitted via POST:

  • User::isUserNameActive() checks that the username exists in the user table and has user_status == 1.
  • User::authenticate() verifies the submitted password against the stored bcrypt hash using password_verify().
  • Auth::login() initializes the session and logs the event.

    $conn = require 'includes/db.php';

Step 4 Post-Login Redirect Logic (Lines 29–36)

After logging in, login.php determines where to send the user:

  1. Forced Password Change: Checks if the user's password is the default reset password ("changeme"). If so, redirects to /user_change_password.php.
  2. Deep-Link Redirect: When an unauthenticated user tries to visit a protected page that calls Auth::requireLogin($page_name, $page_id), they are sent to login.php?page_name=...&page_id=.... Upon login, they are redirected back to that exact page and ID.
  3. Default Landing Page: Redirects to /patient.php.
            if (User::authenticate($conn, $_POST['username'], "changeme")) {
                Url::redirect('/user_change_password.php');
            }
            if (isset($_POST['page_name']) && $_POST['page_name'] != "") {
                Url::redirect('/' . $_POST['page_name'] . '?id=' . $_POST['page_id']);
            } else {
                Url::redirect('/patient.php');
            }

If authentication fails, an error message is set in $error and rendered in a Bootstrap .alert-danger box. When the password is wrong, the hidden redirect fields (page_name, page_id, subfolder) are copied back from $_POST to $_GET so they are not lost if the user tries again:

4. Session Variables Created by Auth::login()

When Auth::login($conn, $username, $subfolder) runs inside classes/Auth.php, it populates $_SESSION with the following keys:

Session Key Value / Type Purpose
$_SESSION['is_logged_in'] true (boolean) Marks the session as authenticated.
$_SESSION['username'] string Logged-in user's username.
$_SESSION['user'] User object Full record from the user table (name, hospital ID, roles, etc.).
$_SESSION['userid'] int Primary key (id) of the user in the user table.
$_SESSION['usergroup'] Ugroup object User group record from user_groups (controls permissions like presult, ppatient, pnbcenter).
$_SESSION['subfolder'] string Subfolder path used by Url::redirect() and Url::currentURL().
$_SESSION['skey'] string (10 chars) Random alphanumeric security key generated via Auth::randomString().
$_SESSION['setSrvTimeLimitIntSecs'] 1200 (int) Server-side idle session timeout limit (1200 seconds = 20 minutes).
$_SESSION['curSrvTimeIntSecs'] int (timestamp) Unix timestamp of the user's login or last activity.
$_SESSION['targetSrvTimeOutIntSecs'] int (timestamp) Expiration timestamp (curTime + 1200). Checked on every protected page via Auth::requireLogin().
$_SESSION['log_username'] & $_SESSION['log_name'] string Used to record audit trail entries in Log::add() on both login and logout.
