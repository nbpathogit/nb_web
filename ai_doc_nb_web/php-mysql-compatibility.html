PHP 7.3 + PHP 8.2+ & MySQL 8.4 Compatibility Guide

Mandatory coding standards for dual PHP/MySQL environment support in nb_web / dev3

1. PHP 8.2+ Dynamic Property Deprecations

When PDO::FETCH_CLASS hydrates objects (such as User or Ugroup) or when session_start() in includes/init.php unserializes $_SESSION['user'] and $_SESSION['usergroup'], PHP 8.2+ emits:

Deprecated: Creation of dynamic property User::$role_a is deprecated in ...\includes\init.php on line 18

Dual-Compatible Fix (PHP 7.3 & PHP 8.2+)

  1. Explicitly declare all database column properties on the PHP class (e.g., public $role_a;, public $user_status;, public $user_type;, public $movetotrash; on User, and public $ugroup_e; on Ugroup).
  2. Place #[\AllowDynamicProperties] on its own line right above the class declaration:
#[\AllowDynamicProperties]
class User
{
    public $id;
    // ...
    public $role_7;
    public $role_a;
    // ...
    public $user_status;
    public $user_type;
    public $movetotrash;
}
Why this works on both PHP 7.3 and PHP 8.2+:
• In PHP 8.2+, #[\AllowDynamicProperties] is parsed as a native Attribute.
• In PHP 7.3, # starts a single-line comment, so PHP 7.3 ignores that line and parses class User on the next line normally.

2. MySQL 8.4 ONLY_FULL_GROUP_BY (SQL Error 1055)

MySQL 8.4 enables sql_mode=only_full_group_by by default. Queries that group by a subset of columns while selecting non-aggregated joined columns fail with:

SQLSTATE[42000]: Syntax error or access violation: 1055 Expression #N of SELECT list is not in GROUP BY clause and contains nonaggregated column ... which is not functionally dependent on columns in GROUP BY clause; this is incompatible with sql_mode=only_full_group_by

Mandatory Rules for Fixing Error 1055

  1. Fix the SQL query directly in the model class — do not rely on disabling sql_mode in classes/Database.php.
  2. Never use ANY_VALUE() — ANY_VALUE() is MySQL-specific and causes a fatal SQL error in MariaDB (used in XAMPP / PHP 7.3 environments).
  3. When grouping 1-to-many rows with GROUP_CONCAT (e.g. Patient::getAllJob1/2/3FinishPhp):
    • Do not add the child table's ID (j.id) to GROUP BY p.id, as that splits a single patient into multiple rows and breaks GROUP_CONCAT.
    • Wrap the non-aggregated child columns in MAX(...):
MAX(j.id) as j_id , 
MAX(j.patient_id) as j_patient_id, 
MAX(j.user_id) as j_user_id, 
MAX(j.job_role_id) as j_job_role_id, 
MAX(j.jobname) as j_jobname,
MAX(j.qty) as j_qty,
p.job1qty as p_job1qty,

GROUP_CONCAT(CONCAT(j.pre_name, j.name, ' ',j.lastname) SEPARATOR ',') AS j_owners,
MAX(DATE(j.finish_date)) as j_finish_date

4. When joined rows are 1-to-1 per group (e.g. ReqSpSlideID::getBillandJobTableWithStart_v2): Include the joined primary keys in GROUP BY (GROUP BY r_id, b.description, b.id, j4.id, j5.id) so MySQL 8.4 recognizes functional dependency for j4.name, j4.lastname, j5.name, and j5.lastname.

3. Required PHP Extensions & System Check (systemchecking.php)

NB Patho relies on several core PHP extensions. These are validated in real time on the Admin page systemchecking.php:

Extension / Class INI Setting Purpose in NB Patho
ZipArchive (ext-zip) extension=zip Decompressing and parsing .xlsx Excel files in patient_edit_by_excel.php and ZIP archive creation.
SimpleXML Built-in Extracting worksheet cells and shared strings from OpenXML spreadsheets.
PDO MySQL (pdo_mysql) extension=pdo_mysql Core database connectivity to nbpa_data / nbpa_data_dev3.
GD extension=gd Slide label printing, barcode rendering, and patient photo processing.
mbstring extension=mbstring UTF-8 multibyte string handling for Thai names and clinical text.
cURL extension=curl Outbound REST API webhooks (e.g. Winmed integration).
Enabling in Laragon / PHP: Ensure extension=zip is uncommented in php.ini. You can verify whether it is loaded by navigating to แอดมินเมนู → ตรวจสอบคำสั่งระบบ (systemchecking.php).
