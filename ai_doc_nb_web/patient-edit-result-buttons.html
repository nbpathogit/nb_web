Result Textarea Action Buttons (Edit, Save, Delete, Reload)

คู่มือศึกษาการทำงานของชุดปุ่มควบคุมประจำกล่องข้อความผลตรวจ <label for="result_message"> ใน patient_edit.php (รวมทั้ง job6_result.php, job7_result.php, และ diagresult.js)

1. โครงสร้างชุดควบคุมกล่องผลตรวจ (UI Mockup)

ในหน้าจอ patient_edit.php แต่ละหัวข้อรายงานผลตรวจ (เรคคอร์ดจากตาราง presultupdate) จะมีแถบควบคุมประจำกล่องข้อความ ประกอบด้วย Label ชื่อหัวข้อ, สถานะการออกผล, ปุ่มเครื่องมือ Edit / Save / Delete / Reload Page, และช่องพิมพ์ข้อความ <textarea>:

Pathological Diagnosis ยังไม่ออกผล
✏️ Edit 💾 Save 📑 Template 🗑️ Delete 🔄 Reload Page
โครงสร้าง HTML ในไฟล์เทมเพลต: includes/patient_form_080_job6_result.php (สำหรับเคสทั่วไป) และ patient_form_080_job7_result.php (สำหรับเซลล์วิทยาปากมดลูก): 
<label for="result_message"><b><?= $presultupdate['result_type'] ?></b></label>
<a id="edit_result_<?= $id ?>" onclick="edit_txt_rs(<?= $id ?>);">Edit</a>
<a id="save_result_<?= $id ?>" onclick="save_txt_rs(<?= $id ?>);" style="display: none;">Save</a>
<a id="delete_result_<?= $id ?>" onclick="delete_txt_rs(<?= $id ?>);">Delete</a>
<textarea ondblclick="edit_txt_rs(<?= $id ?>);" id="txt_rs_<?= $id ?>" readonly>...</textarea>

2. ปุ่ม Edit (แก้ไข) และ Save (บันทึก)

ปุ่ม Edit และ Save ทำงานร่วมกันแบบ State Toggle ในการควบคุมการแก้ไขข้อความใน <textarea>:

คุณสมบัติ ปุ่ม Edit (#edit_result_{id}) ปุ่ม Save (#save_result_{id})
Event Handler onclick="edit_txt_rs(rs_id)" หรือ Double-click บน textarea (ondblclick) onclick="save_txt_rs(rs_id)"
การแสดงผลเริ่มต้น แสดง (หากเคสยังไม่ออกผลและเป็นแพทย์เจ้าของเคส) ซ่อนไว้ (style="display: none;")
สถานะของ Textarea ปลดล็อกเป็นโหมดพิมพ์ได้ (readonly = false) ล็อกกลับเป็นโหมดอ่านอย่างเดียว (readonly = true)
การควบคุมความปลอดภัย เซ็ตแฟล็ก is_diag_editeing_mode = true เพื่อบล็อกปุ่ม Release Report ป้องกันการออกผลระหว่างที่ยังพิมพ์ไม่เสร็จ รีเซ็ตแฟล็ก is_diag_editeing_mode = false เพื่ออนุญาตให้สามารถออกผล Release ได้ตามปกติ
การบันทึกฐานข้อมูล ยังไม่มีการส่งข้อมูล ส่ง AJAX POST ไปยัง ajax_patient_diax_result/save_get_result_message.php

กระบวนการบันทึกของ save_txt_rs(rs_id):

function save_txt_rs(rs_id) {
    // 1. สลับปุ่มกลับมาเป็น Edit
    $("#edit_result_" + rs_id).show();
    $("#save_result_" + rs_id).hide();

    var result_message = $("#txt_rs_" + rs_id).val();

    // 2. ยิง AJAX บันทึกและอ่านค่ากลับเพื่อความถูกต้อง
    $.ajax({
        type: 'POST',
        url: 'ajax_patient_diax_result/save_get_result_message.php',
        data: {
            'rs_id': rs_id,
            'result_message': result_message,
            'patient_id': patient_id,
            'usergroup': usergroup
        },
        success: function (data) {
            var datajson = JSON.parse(data);
            $("#txt_rs_" + rs_id).val(datajson[0].result_message);
        }
    });

    // 3. ล็อก textarea และปลดล็อกสถานะแก้ไข
    $("#txt_rs_" + rs_id).prop('readonly', true);
    is_diag_editeing_mode = false;
}
หมายเหตุการบันทึกประวัติ (Audit Tracking): ใน save_get_result_message.php หากผู้ใช้งานเป็นกลุ่ม Pathologist Admin (usergroup 1900) ระบบจะทำการเรียก Patient::set_update_edit_date($conn, $patient_id) เพื่อบันทึกเวลาแก้ไขล่าสุดของเคสผู้ป่วยโดยอัตโนมัติ

3. ปุ่ม Delete (ลบกล่องข้อความ)

จุดประสงค์: ใช้สำหรับลบกล่องรายงานผลตรวจที่ไม่ต้องการออกไปจากฐานข้อมูลและหน้าจอ

กฎเหล็กด้านความปลอดภัย (Business Rule):
• ปุ่ม Delete จะแสดงเฉพาะเรคคอร์ดของ Group 2 เท่านั้น ($presultupdate['group_type'] == 2) เช่น Pathological Diagnosis, Provisional Diagnosis, Addendum, Revised
• ห้ามลบเด็ดขาดสำหรับ Group 1 และ Group 3: เรคคอร์ดของ Group 1 (Specimen, Gross, Micro) และ Group 3 (Cervical Cytology) เป็นหัวข้อบังคับมาตรฐาน ระบบจะไม่แสดงปุ่ม Delete ให้กด
• หากกล่องข้อความถูก Release ไปแล้ว จะไม่สามารถลบได้เช่นกัน (!$isCurResultReleased)
หัวข้อ รายละเอียด
Element HTML <a class="btn btn-outline-primary btn-sm me-1" id="delete_result_{id}" onclick="delete_txt_rs({id});">Delete</a>
เงื่อนไขแสดงปุ่ม $is_show_delete_btn = $is_show_edit_btn && ($presultupdate['group_type'] == 2);
ขั้นตอนการทำงาน ในฟังก์ชัน delete_txt_rs(rs_id):
1. แสดงกล่องยืนยัน confirm("Delete this report block?")
2. ส่ง AJAX POST ไปที่ ajax_patient_diax_result/delete_result.php
3. ฝั่ง Backend รัน Presultupdate::deleteById($conn, $_POST['rs_id']) ลบแถวออกจากตาราง presultupdate
4. แจ้งเตือน alert("Delete done.")
5. สร้างฟอร์มซ่อนและ Submit อัตโนมัติเพื่อรีเฟรชหน้าจอ (pautoscroll = "end_section")

4. ปุ่ม Reload Page (รีโหลดหน้าจอ)

จุดประสงค์: โหลดหน้าจอ patient_edit.php ใหม่แบบสมบูรณ์ เพื่อให้คอมโพเนนต์ฝั่งเซิร์ฟเวอร์ (Modals และ DataTables) เชื่อมต่อกับกล่องรายงานผลใหม่ที่เพิ่งถูกเพิ่มเข้ามา

หัวข้อ รายละเอียด
Element HTML <a href="patient_edit.php?id={cur_patient_id}&pautoscroll=confirm_result_section_bottom" class="btn btn-outline-primary btn-sm me-1">Reload Page</a>
ตำแหน่งที่ปรากฏ อยู่ในกล่องผลตรวจ Group 2 ที่ถูกสร้างขึ้นมาใหม่แบบไดนามิกผ่านฟังก์ชัน append2page() ใน ajax_patient_diax_result/diagresult.js (บรรทัด 352)
ทำไมต้องมีปุ่มนี้? (Technical Rationale) เมื่อผู้ใช้กดปุ่ม Add New Report Section กล่องผลตรวจจะถูกสร้างผ่าน AJAX และ DOM inject โดยไม่ต้องโหลดหน้าใหม่ทั้งหน้า
อย่างไรก็ดี คอมโพเนนต์ของ Second Pathologist (เช่น Modal เลือกแพทย์คนที่สอง patient_from_080_job6__select_modal.php และตารางประวัติ _tbl_modal.php) เป็น PHP Partials ที่ต้องถูกสร้างขึ้นพร้อมกับ ID ของเรคคอร์ดจากฝั่งเซิร์ฟเวอร์
ดังนั้น ระบบจึงมีปุ่ม Reload Page ให้แพทย์สามารถกดเพื่อรีเฟรชหน้าจอทั้งหน้า พร้อมกระโดดกลับมาที่กล่องผลตรวจเดิม (pautoscroll=confirm_result_section_bottom) เพื่อให้ปุ่มและ Modal ทั้งหมดพร้อมใช้งานอย่างสมบูรณ์แบบ

5. ตารางสรุปเปรียบเทียบทั้ง 4 ปุ่ม (Master Summary)

ปุ่ม Element / Trigger เงื่อนไขการแสดงผล เป้าหมายหลัก / AJAX Endpoint พฤติกรรมหลังกด
Edit #edit_result_{id} / ondblclick ยังไม่ออกผล & เจ้าของเคส Client-side JS ปลดล็อก textarea (readonly=false), ซ่อน Edit, แสดง Save
Save #save_result_{id} ขณะกำลังอยู่ในโหมด Edit save_get_result_message.php บันทึกข้อความลง DB, ล็อก textarea (readonly=true), ซ่อน Save, แสดง Edit
Delete #delete_result_{id} ยังไม่ออกผล & Group 2 เท่านั้น delete_result.php ยืนยันและลบแถวออกจาก presultupdate, รีเฟรชหน้าจอ
Reload Page <a href="...&pautoscroll=..."> กล่องใหม่ที่สร้างผ่าน AJAX (Group 2) Full Page Request (GET) รีโหลดหน้า patient_edit.php ใหม่ทั้งหน้า เพื่อ Bind Modal และ Job ของ Second Patho
