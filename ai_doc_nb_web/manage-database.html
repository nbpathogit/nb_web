1. ภาพรวมของระบบจัดการฐานข้อมูล (Overview)

หน้า manage_database.php พัฒนาขึ้นเพื่อให้ผู้ดูแลระบบ (Admin: Group 1000) สามารถตรวจสอบ สำรวจข้อมูล ดูโครงสร้างฟิลด์ ส่งออกข้อมูล และรันคำสั่ง SQL วิเคราะห์ข้อมูลได้อย่างสะดวกรวดเร็ว โดยเข้าถึงได้ผ่านเมนู Admin (ผู้ดูแลระบบ) > จัดการฐานข้อมูล

คุณสมบัติ (Feature) คำอธิบาย เทคโนโลยีที่ใช้
All Tables Overview ดูรายชื่อตารางทั้งหมด 36 ตาราง พร้อมนับจำนวนแถวที่แท้จริง (Exact Row Count), ขนาดข้อมูล (Data Length), ขนาด Index และ Comment information_schema.TABLES + SELECT COUNT(*)
SQL Query Console กล่องรันคำสั่ง SQL SELECT ปรับแต่งได้เองอิสระ อยู่ด้านบนสุดของทุกหน้า พร้อมจับเวลาประมวลผล (Execution Time ms) PDO Prepared Query + Microtime Benchmark
SearchPanes Filter ตัวกรองข้อมูลแบบ Multi-faceted (Panes) จัดวางแถวละ 5 คอลัมน์ (Columns-5) สวยงามตามธีม NB Patho DataTables SearchPanes 2.x + Select

2. SQL Query Console (กล่องรันคำสั่ง SQL ด้านบน)

กล่อง SQL Console ด้านบนช่วยให้แอดมินสามารถเขียนคำสั่งดึงข้อมูลได้ทันทีโดยไม่ต้องเข้า phpMyAdmin:

2.1 ระบบความปลอดภัย (Safety Constraint)

Security Guard: ระบบอนุญาตให้รันเฉพาะคำสั่งที่ขึ้นต้นด้วย SELECT, SHOW, DESCRIBE, หรือ EXPLAIN เท่านั้น เพื่อป้องกันอุบัติเหตุจากการแก้ไขหรือลบข้อมูลในระบบจริง (ไม่อนุญาต UPDATE, DELETE, DROP, ALTER)

2.2 ปุ่มการทำงาน 3 รูปแบบ

ปุ่ม การทำงาน เหมาะสำหรับ
Run SQL (แสดงบนเว็บ) ประมวลผลและนำผลลัพธ์มาพล็อตเป็นตารางบนหน้าเว็บ พร้อมเปิดใช้งาน SearchPanes และปุ่มค้นหา การค้นหาข้อมูลไม่เกิน 1,000 แถว หรือต้องการดูและกรองข้อมูลทันที
ดาวน์โหลดเป็น Excel โดยตรง สตรีมข้อมูลแถวต่อแถวส่งเป็นไฟล์ Excel (.xls) ทันที โดยไม่พล็อตลงหน้าเว็บ ข้อมูลจำนวนมาก (หลายหมื่นแถว) ที่ต้องการนำไปเปิดในโปรแกรม Excel โดยที่เบราว์เซอร์ไม่ค้าง
CSV สตรีมข้อมูลผลลัพธ์เป็นไฟล์ .csv พร้อม UTF-8 BOM สำหรับเปิดใน Excel หรือโปรแกรมวิเคราะห์ข้อมูล ข้อมูลขนาดใหญ่มากๆ หรือต้องการนำเข้าโปรแกรม BI/Python/R

2.3 ระบบป้องกันดาวน์โหลดไฟล์ว่าง (0-Row Protection)

เมื่อผู้ใช้กดปุ่ม "ดาวน์โหลดเป็น Excel โดยตรง" แต่คำสั่ง SQL นั้นมีผลลัพธ์ 0 แถว (เช่น เงื่อนไข WHERE ไม่ตรงกับข้อมูลจริง):

  • ระบบจะ ไม่ดาวน์โหลดไฟล์เปล่า ขนาด 800 ไบต์ที่มีแต่หัวตาราง
  • ระบบจะแสดงแบนเนอร์แจ้งเตือนสีแดงให้ทราบทันทีว่าคำสั่งทำงานสำเร็จแต่ไม่พบข้อมูล พร้อมแสดง SQL ที่ส่งไป เพื่อให้ผู้ใช้ปรับปรุงเงื่อนไข WHERE

2.4 ระบบบันทึกและเรียกใช้คำสั่ง SQL ภายหลัง (Saved SQL Queries via Database)

เพื่ออำนวยความสะดวกในการใช้งานคำสั่ง SQL ที่ใช้บ่อยหรือคำสั่งที่มีการ JOIN ซับซ้อน ระบบจัดเก็บคำสั่ง SQL ลงในตารางฐานข้อมูลโดยตรง (saved_sql_query):

ฟังก์ชัน วิธีการใช้งาน ผลลัพธ์
บันทึก SQL ใหม่ พิมพ์คำสั่ง SQL ในกล่องข้อความ → กดปุ่ม บันทึก SQL นี้ → ตั้งชื่อคำอธิบาย → กดบันทึก คำสั่งจะถูก INSERT ลงตาราง saved_sql_query และเพิ่มเข้าใน Dropdown ทันทีผ่านระบบ AJAX
เรียกใช้ SQL ที่บันทึกไว้ คลิกเลือกชื่อคำสั่งจาก Dropdown "SQL ที่บันทึกไว้:" ระบบจะดึงคำสั่ง SQL มาใส่ใน Textarea ให้อัตโนมัติ พร้อมแสดง Badge โหลดแล้ว และปุ่มลบ
อัพเดท (เซฟทับคำสั่งเดิม) เมื่อแก้ไขคำสั่งใน Textarea จะมี Badge สีเหลืองเตือน มีการแก้ไข → กดปุ่มสีส้ม อัพเดท (เซฟทับ) → ป๊อปอัปจะเลือกโหมดบันทึกทับให้อัตโนมัติ → กดยืนยัน (คงอยู่ตลอดแม้หลังกด Run SQL) คำสั่ง SQL และชื่อในรายการเดิมจะถูก UPDATE ทันที พร้อมบันทึกเวลา stampdateedit บนฐานข้อมูล
เซฟเป็นอันใหม่ (Save As New) เมื่อต้องการนำคำสั่งเดิมมาต่อยอดเป็นอีกคำสั่ง → กดปุ่ม เซฟเป็นอันใหม่ → ตั้งชื่อรายการใหม่ → กดบันทึก คำสั่งใหม่จะถูกเพิ่มเป็นเรคคอร์ดใหม่ขึ้นต้น Dropdown โดยไม่ทับคำสั่งเดิม พร้อมบันทึกเวลา stampdatecreate
ลบคำสั่ง SQL เลือกคำสั่งจาก Dropdown → กดปุ่มลบ (รูปถังขยะสีแดง) → กดยืนยัน คำสั่งจะถูก DELETE ออกจากตาราง saved_sql_query และนำออกจาก Dropdown ทันที
โครงสร้างตารางฐานข้อมูล saved_sql_query:
  • id (INT AUTO_INCREMENT PRIMARY KEY) - รหัสคำสั่ง
  • title (VARCHAR(255)) - ชื่อหรือคำอธิบายคำสั่ง SQL
  • sql_query (MEDIUMTEXT) - โค้ดคำสั่ง SQL
  • created_by (INT NULL) - รหัสผู้ใช้ที่สร้างคำสั่ง
  • stampdatecreate (DATETIME) - วันเวลาที่บันทึกคำสั่ง (DEFAULT CURRENT_TIMESTAMP)
  • stampdateedit (DATETIME NULL) - วันเวลาที่แก้ไขล่าสุด (ON UPDATE CURRENT_TIMESTAMP)

3. ข้อควรระวัง: โครงสร้างข้อมูลตาราง service_billing

ทำไมฟิลด์ name และ lastname ใน service_billing ถึงเป็นค่าว่าง?
ในตาราง service_billing ข้อมูลผู้ป่วยจริง (ชื่อ, นามสกุล, โรงพยาบาล) ถูกแยกเก็บไว้ที่ตารางหลัก patient โดยใน service_billing จะเก็บเพียงรหัสอ้างอิง patient_id เท่านั้น ดังนั้นทั้ง 78,514 แถวในฟิลด์ name และ lastname ของตารางนี้จึงเป็นค่าว่างตามการออกแบบฐานข้อมูลเดิม

ตัวอย่างคำสั่ง SQL ที่ถูกต้องในการดึงข้อมูลบิลพร้อมชื่อผู้ป่วย:

SELECT 
    b.id, 
    b.number AS sn_number, 
    p.pname AS patient_name, 
    p.plastname AS patient_lastname, 
    p.phospital_num AS hn,
    b.code_description, 
    b.description, 
    b.cost, 
    b.import_date
FROM service_billing b
LEFT JOIN patient p ON b.patient_id = p.id
ORDER BY b.id DESC
LIMIT 100;

4. สถาปัตยกรรม Direct Streaming Export (ทำไมถึงเร็ว?)

การส่งออกข้อมูลปกติในเว็บแอปพลิเคชันทั่วไปมักประสบปัญหา "Memory Limit Exceeded" หรือ "Browser Freeze" เมื่อต้องส่งออกข้อมูล 80,000+ แถว เพราะระบบมักจะโหลดข้อมูลทั้งหมดเข้า RAM ก่อน (fetchAll) แล้วจึงสร้างหน้าเว็บ

ใน manage_database.php เราใช้สถาปัตยกรรม Row-by-Row Direct Streaming:

  1. Output Buffer Cleaning: ล้าง Buffer ทั้งหมดด้วย while (ob_get_level()) { ob_end_clean(); } ก่อนส่ง Headers เพื่อให้การส่งข้อมูลเริ่มต้นทันทีโดยไม่มีการรอ
  2. Unbuffered Cursor Fetch: วนลูปด้วย while ($row = $sqlStmt->fetch(PDO::FETCH_ASSOC)) ทีละแถว แล้วพ่นออกทาง Socket ทันที
  3. Microsoft Excel XML Header: ใส่ XML Envelope <x:ExcelWorkbook> พร้อม <x:DisplayGridlines/> และ CSS mso-number-format:\@; ป้องกันไม่ให้ Excel แปลงตัวเลข HN / ID ยาวๆ เป็นเลขยกกำลัง (Scientific Notation)
