Database & Report Architecture

ReportType Groups (1, 2, 3) & UResult Lifecycle

คู่มือสถาปัตยกรรมตารางฮาร์ดโค้ด report_type ทั้ง 3 กลุ่ม, ตรรกะการวนลูปสร้างเรคคอร์ด uresult (ในตาราง presultupdate) ใน patient_add.php และการเพิ่ม On-Demand ใน patient_edit.php

1. ภาพรวมสถาปัตยกรรม Report Groups ทั้ง 3 กลุ่ม

ในระบบ NB Patho โครงสร้างหัวข้อรายงานผลตรวจทางพยาธิวิทยา (Report Sections) จะถูกจัดกลุ่มผ่านฟิลด์ group_type ในตารางฐานข้อมูล report_type โดยแบ่งออกเป็น 3 กลุ่มตามลักษณะการทำงานและประเภทของเคส:

Group 1 group_type = 1

Mandatory Base Descriptive
สร้างอัตโนมัติตอนเพิ่มเคสทั่วไป

  • ใช้กับเคส: SN, CN, FN, DN, IN, ZN
  • สถานะเริ่มต้น: ยังไม่ออกผล
  • ห้ามลบ ในหน้าจอ Edit
  • สร้างใน: patient_add.php

Group 2 group_type = 2

Diagnostic & Revision (On-Demand)
เพิ่มตามต้องการในหน้าแก้ไขเคส

  • ใช้กับเคส: ทั่วไปที่ไม่ใช่ PN/LN
  • สถานะเริ่มต้น: ออกผลแล้ว / ออกผลเบื้องต้น
  • ลบได้ ก่อน Release
  • สร้างใน: patient_edit.php (Modal)

Group 3 group_type = 3

Cervical Cytology Mandatory
สร้างอัตโนมัติสำหรับเซลล์วิทยาปากมดลูก

  • ใช้กับเคส: PN, LN
  • สถานะเริ่มต้น: ออกผลแล้ว
  • ห้ามลบ ในหน้าจอ Edit
  • สร้างใน: patient_add.php
ตรรกะการแยกสร้างใน patient_add.php: เมื่อเคสคนไข้ถูกบันทึกลงฐานข้อมูล ($patient->create($conn)) ระบบจะตรวจสอบเงื่อนไข:
• หาก $sn_type == 'PN' || $sn_type == 'LN' → วนลูปสร้างจาก Group 3 (5 หัวข้อ)
• เคสอื่น ๆ ทั้งหมด (SN, CN, etc.) → วนลูปสร้างจาก Group 1 (4 หัวข้อ)
• หมายเหตุ: Group 2 ยังไม่ได้ถูกเรียกใช้ใน patient_add.php แต่จะถูกเรียกใช้ผ่าน Modal ในหน้า patient_edit.php เมื่อแพทย์ลงผลวินิจฉัย

2. Group #1 — Mandatory Base Descriptive (สร้างใน patient_add.php)

คอนดิชั่นและโครงสร้างของ Group 1 ถูกฮาร์ดโค้ดไว้ในฐานข้อมูล report_type โดยอ่านผ่านคำสั่ง SQL:

SELECT *
FROM `report_type`
WHERE group_type = 1
ORDER BY id;

ตารางข้อมูลฮาร์ดโค้ด Group 1 (4 เรคคอร์ด):

id group_type name (ชื่อหัวข้อหลัก) release_type options
1 1 Specimen ยังไม่ออกผล (NULL/ว่าง)
2 1 Clinical Diagnosis ยังไม่ออกผล (NULL/ว่าง)
3 1 Gross Description ยังไม่ออกผล (NULL/ว่าง)
4 1 Microscopic Description ยังไม่ออกผล (NULL/ว่าง)

โค้ดการวนลูปสร้าง Record ใน patient_add.php (บรรทัด 226–238):

// เมื่อไม่ใช่เคส PN หรือ LN (คือ SN, CN, FN, DN, IN, ZN)
$cur_patient_id = $patient->id;
$typelists = ReportType::getAllbyGroup1($conn);

foreach ($typelists as $typelist) {
    $resultreport = Presultupdate::getInitObj();
    $resultreport->group_type = $typelist['group_type'];     // 1
    $resultreport->patient_id = $cur_patient_id;             // ผูกกับคนไข้เคสนี้
    $resultreport->result_type = $typelist['name'];          // นำ name ไปเป็นชื่อหัวข้อหลัก
    $resultreport->result_type_id = $typelist['id'];         // ID (1, 2, 3, 4)
    $resultreport->release_type = $typelist['release_type']; // 'ยังไม่ออกผล'
    $resultreport->create($conn);
}
ข้อควรทราบพิเศษเกี่ยวกับ PDF (Group 1): ในการสร้างรายงานผลทางพยาธิวิทยา (patient_pdf.php) ผลตรวจ Group 1 จะถูกพิมพ์เรียงแบบ ASC (id 1, 3, 4) อยู่ด้านล่างผลตรวจ Group 2 โดย result_type_id == 2 (Clinical Diagnosis) จะถูกข้าม ไม่ถูกนำมาพิมพ์ลงใน PDF

3. Group #2 — Diagnostic & Revision (ยังไม่ได้ถูกเรียกใช้ใน patient_add.php)

Group 2 เป็นหัวข้อการวินิจฉัยโรคและการแก้ไขรีพอท ซึ่งไม่ได้ถูกเรียกใช้ตอนเพิ่มคนไข้ (patient_add.php) แต่จะถูกเรียกใช้งานเมื่อเข้าสู่ขั้นตอนการอ่านผลวินิจฉัยใน patient_edit.php ผ่าน Modal เลือกชนิดรายงาน (includes/patient_form_080_job6__select_rs_modal.php):

SELECT *
FROM `report_type`
WHERE group_type = 2
ORDER BY id;

ตารางข้อมูลฮาร์ดโค้ด Group 2 (4 เรคคอร์ด):

id group_type name (ชื่อหัวข้อหลัก) release_type options
11 2 Provisional Diagnosis ออกผลเบื้องต้น (NULL/ว่าง)
12 2 Pathological Diagnosis ออกผลแล้ว (NULL/ว่าง)
13 2 Addendum ออกผลแล้ว (NULL/ว่าง)
14 2 Revised ออกผลแล้ว (NULL/ว่าง)

พฤติกรรมและการทำงานของ Group 2:

  • การเพิ่มหัวข้อ: แพทย์เลือกหัวข้อจาก Dropdown ใน Modal #add_result_type_modal เพื่อสร้างเรคคอร์ด presultupdate ใหม่ตามต้องการ
  • การลบหัวข้อ (Deletable): ในหน้าจอ patient_edit.php ปุ่มลบสีแดงจะแสดงให้กดลบได้เฉพาะเรคคอร์ดที่เป็น group_type == 2 เท่านั้น (ก่อนที่จะทำการ Release)
  • Second Pathologist (Role 6): การดับเบิ้ลคอนเฟิร์มผลจะถูกผูกเข้ากับเรคคอร์ด Group 2 นี้
  • การพิมพ์ PDF: ใน patient_pdf.php ผลตรวจของ Group 2 จะถูกจัดพิมพ์ไว้บนสุดของรายงาน เรียงลำดับแบบ DESC โดยใช้เทมเพลตฟอนต์ขนาด 22pt (patient_format_result_pdf_2.php)

4. Group #3 — Mandatory Cervical Cytology (สร้างใน patient_add.php)

สำหรับเคสเซลล์วิทยาปากมดลูก (PN และ LN) จะถูกฮาร์ดโค้ดให้อ่านและสร้างจาก Group 3:

SELECT *
FROM `report_type`
WHERE group_type = 3 
ORDER BY id;

ตารางข้อมูลฮาร์ดโค้ด Group 3 (5 เรคคอร์ด):

id group_type name (ชื่อหัวข้อหลัก) release_type options
21 3 SPECIMEN TYPE ออกผลแล้ว (NULL/ว่าง)
22 3 SOURCE ออกผลแล้ว (NULL/ว่าง)
23 3 SPECIMEN ADEQUACY ออกผลแล้ว (NULL/ว่าง)
24 3 INTERPRETATION ออกผลแล้ว (NULL/ว่าง)
25 3 EDUCATIONAL NOTES AND SUGGESTION ออกผลแล้ว (NULL/ว่าง)

โค้ดการวนลูปสร้าง Record ใน patient_add.php (บรรทัด 214–225):

// เมื่อเป็นเคส PN หรือ LN
if ($sn_type == 'PN' || $sn_type == 'LN') {
    $cur_patient_id = $patient->id;
    $typelists = ReportType::getAllbyGroup3($conn);

    foreach ($typelists as $typelist) {
        $resultreport = Presultupdate::getInitObj();
        $resultreport->group_type = $typelist['group_type'];     // 3
        $resultreport->patient_id = $cur_patient_id;             // ผูกกับคนไข้เคสนี้
        $resultreport->result_type = $typelist['name'];          // นำ name ไปเป็นชื่อหัวข้อหลัก
        $resultreport->result_type_id = $typelist['id'];         // ID (21-25)
        $resultreport->release_type = $typelist['release_type']; // 'ออกผลแล้ว'
        $resultreport->create($conn);
    }
}
