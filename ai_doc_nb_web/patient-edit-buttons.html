Diagnostic Action Buttons Architecture

คู่มือศึกษาปุ่มควบคุมการวินิจฉัยและออกผลตรวจ 4 ปุ่มหลักใน patient_edit.php (รวมถึง job6_result.php และ job7_result.php) พร้อมเงื่อนไขการแสดงผล, เหตุการณ์ Client JS, AJAX endpoints, และกระบวนการเปลี่ยนสถานะ

1. ปุ่มควบคุมผลตรวจทั้ง 4 ปุ่ม (Visual Preview)

ปุ่มควบคุมหลักชุดนี้จะอยู่ที่ด้านล่างของส่วนรายงานผลตรวจทางพยาธิวิทยา (เรนเดอร์ใน includes/patient_form_080_job6_result.php สำหรับเคสชิ้นเนื้อทั่วไป และ patient_form_080_job7_result.php สำหรับเคสเซลล์วิทยาปากมดลูก):

Start Diagnostic Add New Report Section. Request Second Pathologist Review Release Report
Stage 1 • Status 12000

Start Diagnostic

เลื่อนสถานะเคสเข้าสู่การวินิจฉัย (12000) สำหรับแพทย์เจ้าของเคส

Stage 2 • On-Demand

2. ปุ่มที่ 1: Start Diagnostic (#btnmove12000)

จุดประสงค์: ใช้เมื่อแพทย์ผู้อ่านผล (Primary Pathologist) หรือนักเซลล์วิทยา (Cytologist) พร้อมเริ่มบันทึกผลการวินิจฉัย โดยจะเปลี่ยนสถานะจากขั้นตอนก่อนหน้า (เช่น เตรียมสไลด์แล้ว 6000 หรือทำแลปน้ำ 10000) เข้าสู่สถานะ 12000 (อ่านผลการวินิจฉัย)

หัวข้อ รายละเอียด
Element HTML <button name="btnmove12000" id="btnmove12000" type="submit" class="btn btn-primary">Start Diagnostic</button>
เงื่อนไขแสดง/เปิดใช้ (Enable) $curstatusid != "12000" && ($isCurrentPathoIsOwnerThisCase || $isPersonOwnThisCase) && !$isCurUserCust
• สถานะปัจจุบันต้องยังไม่ใช่ 12000
• ผู้ใช้งานที่ล็อกอินอยู่ต้องเป็นเจ้าของเคส (Primary Pathologist/Cytologist)
• ต้องไม่ใช่กลุ่มลูกค้า (Customer)
Client JavaScript ไฟล์ ajax_patient_diax_result/patient_status_control.js (บรรทัด 501–524):
สร้าง Form บน DOM แล้ว Submit POST: 
status = 12000
cur_status = <cur_status>
isset_date_first_report = <val>
pautoscroll = "confirm_result_section_bottom"
isautoeditmode = "NA"
Backend PHP ใน patient_edit.php (บรรทัด 62):
• เรียก Patient::updateStatusWithMoveDATE() เพื่อเปลี่ยน status_id = 12000 และประทับเวลา date_12000 = NOW()
• เซ็ต pautoscroll = "confirm_result_section_bottom" เพื่อให้หน้าจอกระโดดไปยังส่วนลงผลทันทีหลังรีเฟรช

3. ปุ่มที่ 2: Add New Report Section (#add_new_report_section_btn)

จุดประสงค์: ใช้สำหรับเพิ่มกล่องข้อความรายงานผลเพิ่มเติม (Group 2) เช่น Pathological Diagnosis, Provisional Diagnosis, Addendum, หรือ Revised Report

หัวข้อ รายละเอียด
Element HTML <button class="btn btn-primary" id="add_new_report_section_btn" data-bs-toggle="modal" data-bs-target="#add_result_type_modal">Add New Report Section.</button>
เงื่อนไขแสดง/เปิดใช้ (Enable) $curstatusid == "12000" && $isCurrentPathoIsOwnerThisCase && !$isLastReleaseGroup2DateNull
• สถานะเคสต้องอยู่ที่ 12000
• บล็อกสำคัญ: กล่องผลตรวจ Group 2 ก่อนหน้านี้ต้องถูก Release ไปแล้วเรียบร้อย (!$isLastReleaseGroup2DateNull) ถึงจะอนุญาตให้เพิ่มกล่องใหม่ได้ เพื่อป้องกันการเปิดกล่องซ้อนกันโดยยังไม่ออกผลกล่องเดิม
Modal & การทำงาน เปิด Modal #add_result_type_modal (includes/patient_form_080_job6__select_rs_modal.php) ให้เลือกจากรายการ Group 2 (IDs 11–14):
• เมื่อกดยืนยัน #add_u_result จะส่ง AJAX POST ไปยัง ajax_patient_diax_result/new_result.php
• ส่งพารามิเตอร์: cur_patient_id, group_type = 2, result_type_id, result_type, release_type
ผลลัพธ์ในฐานข้อมูล & DOM • เพิ่มเรคคอร์ดใหม่ลงตาราง presultupdate
• ฟังก์ชัน append2page(data) ใน diagresult.js นำ HTML กล่องใหม่มาแทรกในหน้าจอทันทีโดยไม่ต้องโหลดใหม่ทั้งหน้า
• ปิดปุ่ม (disable) #add_new_report_section_btn ชั่วคราว และเปิดปุ่ม #btn_release

4. ปุ่มที่ 3: Request Second Pathologist Review (#btn2review13000)

จุดประสงค์: ส่งเคสให้แพทย์ผู้ช่วยคอนเฟิร์มผล (Second Pathologist / Job Role 6) ตรวจสอบและให้ความเห็นชอบก่อนการออกผลจริง โดยเลื่อนสถานะเคสเข้าสู่ 13000 (วินิจฉัยคอนเฟิร์ม)

หัวข้อ รายละเอียด
Element HTML <button name="btn2review13000" id="btn2review13000" class="btn btn-primary">Request Second Pathologist Review</button>
เงื่อนไขแสดง/เปิดใช้ (Enable) $isCurrentPathoIsOwnerThisCase && $isLastReleaseGroup2SecondPathoAval && $isLastedResultReleaseDateNULL && $curstatus[0]['id'] == 12000
• สถานะต้องเป็น 12000
• ต้องเป็นแพทย์เจ้าของเคส (Primary Pathologist)
• ต้องมีการเลือกแพทย์ Second Pathologist ใน Dropdown ของกล่องผลตรวจแล้ว ($isLastReleaseGroup2SecondPathoAval)
• ผลตรวจกล่องล่าสุดต้องยังไม่ได้ถูก Release
Client AJAX & Submit ใน patient_status_control.js (บรรทัด 595–666):
1. ส่ง AJAX ไปที่ ajax_patient_diax_result/set_second_patho_review.php เซ็ต second_patho_review = 1 (1 = wait for review)
2. อัปเดตทั้งในตาราง job, presultupdate, และ patient
3. Submit POST Form: status = 13000, pautoscroll = "confirm_result_section"
พฤติกรรมในสถานะ 13000 (สำหรับ Second Patho) เมื่อ Second Pathologist เข้าดูเคส จะพบปุ่มควบคุมพิเศษ 2 ปุ่ม:
• btnrejto12000 Reject to originator: รีเซ็ต second_patho_review = 0 ส่งสถานะกลับไปเป็น 12000 ให้แพทย์คนแรกแก้ไข
• btnagreeto20000 Agree with result and release report: เซ็ต second_patho_review = 2 (approved) และส่งเคสไปออกผลที่สถานะ 20000 ทันที

5. ปุ่มที่ 4: Release Report (#btn_release)

จุดประสงค์: ทำการอนุมัติและออกผลการตรวจทางพยาธิวิทยาขั้นสุดท้าย เปลี่ยนสถานะเคสเป็น 20000 (ออกผลแล้ว / เสร็จสิ้น) ประทับเวลาออกผลอย่างเป็นทางการ และสั่งสร้างไฟล์รายงาน PDF โดยอัตโนมัติ

หัวข้อ รายละเอียด
Element HTML <button name="btn_release" id="btn_release" type="submit" class="btn btn-primary">Release Report</button>
เงื่อนไขแสดง/เปิดใช้ (Enable) $isCurrentPathoIsOwnerThisCase && $curstatus[0]['id'] == 12000 && $isLastReleaseGroup2DateNull
• อยู่ในสถานะ 12000 และเป็นแพทย์เจ้าของเคส
• ผลตรวจกล่องล่าสุดยังไม่มีการประทับเวลา Release
Security & Validation Checks ก่อนส่ง ระบบใน patient_status_control.js (บรรทัด 676–753) จะทำการตรวจสอบ:
1. !is_diag_editeing_mode → ต้องบันทึกข้อความที่กำลังพิมพ์ให้เสร็จก่อน
2. get_spcimen_list1_count() > 0 → ต้องมีการคิดราคาชิ้นเนื้อ (Specimen Price) อย่างน้อย 1 รายการ
3. Second Patho Gate: หากมีการเลือกแพทย์ Second Pathologist ไว้ (lastest_SecondPatho_userid != '0') ระบบจะแจ้งเตือน "Second patho need to be agree first!" และไม่อนุญาตให้ออกผลตรง ต้องส่งให้ Second Patho ตรวจก่อน
4. กล่องยืนยัน: "คุณกำลังจะออกผลถึงลูกค้า! หากออกผลแล้วคุณจะไม่สามารถแก้ไขผลที่ออกไปแล้วได้"
กระบวนการ Release (AJAX & Backend) 1. ส่ง AJAX ไปที่ ajax_patient_diax_result/setReleaseTimeIfNull.php ประทับเวลา release_time = NOW() ลงในเรคคอร์ด presultupdate ทุกรายการที่ยังไม่มีเวลาออกผล
2. ประทับ date_first_report (หากเป็นการออกผลครั้งแรก)
3. Submit POST: status = 20000, reported_as = 'ออกผลแล้ว' (หรือ 'ออกผลเบื้องต้น'), pautoscroll = "finish_section", auto_release_pdf = 1
4. patient_edit.php รัน Patient::updateStatusWithMoveDATE() บันทึก date_20000 = NOW()
5. Auto PDF Generation: โค้ดเรียก require 'patient_pdf.php' อัตโนมัติด้วย $pdfOutputOption = 'F' เพื่อสร้างไฟล์ PDF บนเซิร์ฟเวอร์

ปุ่ม Element ID สถานะเริ่มต้น สถานะปลายทาง ผู้มีสิทธิ์กด ผลลัพธ์หลัก
Start Diagnostic #btnmove12000 6000 / 10000 / อื่น ๆ 12000 Primary Pathologist / Cytologist เริ่มขั้นตอนการวินิจฉัย บันทึก date_12000
