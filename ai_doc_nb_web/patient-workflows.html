Patient Workflows Reference

patient.php, patient_add.php, patient_edit.php (Status 1000→20000), and PDF Attachments

1. Patient List (patient.php & data/patient.php)

  • DataTable Feed: js/patient.js requests JSON from data/patient.php, which calls Patient::getAllJoin_v2($conn, 0, $range).
  • Customer Filtering: For customer groups 5000 and 5100, data/patient.php only returns rows matching $_SESSION['user']->uhospital_id == $patient['phospital_id'] and excludes IN and ZN prefixes.
  • POST Management Actions: trash_id calls Patient::movetotrash(); delete_id calls Patient::delete2().

2. Patient Add (patient_add.php & includes/patient_form_005_add_pat_num.php)

A. Authentication & Role Restrictions

  • Session Gate: Calls Auth::isLoggedIn() and redirects unauthenticated users to /login.php.
  • Role Restriction: Loads user_auth.php and blocks customer user groups ($isCurUserClinicianCust / 5000 and $isCurUserHospitalCust / 5100) from viewing or submitting the form.
  • Initial Flags: Sets $isAddPage = true, $isEditModePageOn = true, $isEditModePageForPatientInfoDataOn = true, and $curstatus[0]['id'] = 1000 (includes/status_cur.php).

B. Surgical Number (pnum) Generation Modes (POST Handler)

  • Auto Mode ($_POST['is_autogen'] == "yes"):
    • Reads prefix $sn_type = $_POST['snprefix'] (from SnPrefix::getAll($conn): SN, CN, PN, LN, FN, DN, IN, ZN).
    • Gets 2-digit year via Util::get_curreint_year().
    • Checks Patient::get_count_sn_year($conn, $curyear): if 0, sets $runnum = 1; otherwise queries Patient::get_max_sn_run_by_year($conn, $curyear, $sn_type) (WHERE sn_year = :sn_year AND sn_type = :sn_type AND movetotrash = 0) and increments max_sn_run by 1.
    • Zero-pads to 5 digits via Util::prepend_string_with_zero(5, $runnum) to form $patientNumber = $sn_type . $curyear . $runstr (e.g., SN2600001).
  • Manual Mode ($_POST['is_autogen'] == "no"): Concatenates $_POST['prenum'] (2 chars), $_POST['yearnum'] (2 digits), and zero-padded (int)$_POST['runnum'] (5 digits).

C. Model Initialization, Sub-Patient Cloning (super_id) & Persistence

  • Default Template vs. Sub-Patient:
    • For a new root case, loads defaults from Patient::getInit() (status_id = 1000, priority_id = 5, p_speciment_type = "lump", pedge = -1, isautoeditmode = "patient_detail_section", pautoscroll = "patient_detail_section").
    • If $_POST['super_id'] is present (when creating a linked sub-case from patient_edit.php), fetches the parent case via Patient::getAll($conn, $_POST['super_id']) for fallback defaults and clears isautoeditmode = "" and pautoscroll = "".
  • Database Insert: Calls $patient->create($conn), stamping create_date and date_1000 with Util::get_curreint_thai_date_time(), recording create_by, and logging via Log::add().

D. Post-Create Dependent Records & Redirect

  • Initial Report Sections (presultupdate):
    • If $sn_type == 'PN' || $sn_type == 'LN', creates Presultupdate rows from ReportType::getAllbyGroup3($conn).
    • Otherwise (SN, CN, FN, DN, IN, ZN), creates Presultupdate rows from ReportType::getAllbyGroup1($conn).
  • Quality Questionnaires: Creates a blank QuesSN row (q_sn) when $sn_type == 'SN', or a blank QuesCN row (q_cn) when $sn_type == 'CN'.
  • Redirect: Redirects to /patient_edit.php?id=$patient->id.

4. Patient PDF Attachments (pdf_attach_upload.php & classes/Pdfattach.php)

  • Upload Form: Rendered inside attach_pdf_section in patient_edit.php. Submits file, patient_id, and pnum via FormData AJAX to pdf_attach_upload.php.
  • Storage & Conversion: Moves the uploaded PDF into pdf_attach_uploads/<pnum>_<timestamp>/, attempts 300-dpi PDF-to-JPG conversion via ImageMagick, and persists the record in pdf_attach via Pdfattach::create().

5. Batch Result Import by Excel (patient_edit_by_excel.php)

A specialized utility allowing authorized pathologists (Group 2000 / 1900) and system administrators (Group 1000) to upload an Excel file (.xlsx) and update diagnosis results across multiple surgical numbers in batch.

A. Column Specification (Learned from C:\anuchit2\example upload result NB.xlsx)

Column Name Database Field Target Section / Result Type Notes
sn patient.pnum Primary key for lookup Matches surgical number (e.g., CN2601596, SN2612105)
Specimen presultupdate.result_message Specimen (Group 1, ID: 1) Case-insensitive direct match
Clinical diagnosis presultupdate.result_message Clinical Diagnosis (Group 1, ID: 2) Excluded from 'Diag' matching
Gross presultupdate.result_message Gross Description (Group 1, ID: 3) Smart synonym match for macroscopic / gross
Micro presultupdate.result_message Microscopic Description (Group 1, ID: 4) Smart synonym match for microscopic / micro
Diag presultupdate.result_message Pathological Diagnosis (Group 2, ID: 12) Strictly resolves to Pathological Diagnosis

B. Execution Pipeline per Row

  1. Select SN: Queries patient by pnum = :sn and verifies active state (movetotrash = 0). Retrieves patient.id.
  2. Validate Ownership: Checks patient.ppathologist_id and Job Role 5 (job_role_id = 5). If current logged-in pathologist is not the owner, skips row with explanatory warning. (Admin override toggle available).
  3. Fetch Existing uresult: Queries all rows from presultupdate for the retrieved patient_id.
  4. Loop Columns & Update: Matches each Excel column to uresult.result_type:
    • Release Status Check: If status is ออกผลเบื้องต้น or ออกผลแล้ว (case reported_as, status_id = 20000, or result release_time set), skips update with RELEASED_SKIPPED to protect signed-out reports.
    • Auto-create 'Diag': If looping through uresult does not find a match for column Diag, automatically creates a new Pathological Diagnosis record (Group 2, ID: 12) in presultupdate and inserts the diagnosis text.
    • If matched and changed → updates result_message and logs audit history via Log::add().
    • If matched and identical → logs UNCHANGED (no update needed).
    • If empty → logs EMPTY_SKIPPED (preserves existing text).
    • If not matched (and non-Diag) → prints explicit error note explaining why it cannot be inserted.

C. Interactive Tools

  • Dry Run (Simulation Mode): Preview row matching, character counts, and diffs without committing changes to MySQL.
  • Sample Download: Direct download endpoint for example upload result NB.xlsx.
  • Step Log Table: Per-row badge summary with detailed action history and direct links to each case.

6. History Report Section (patient_edit.php)

A dedicated retrospective section placed immediately after รับเข้า/ใส่ข้อมูลผู้ป่วย (#patient_detail_section) and before สิ่งส่งตรวจ และ แพทย์ผู้ตรวจ (#patient_plan_section).

A. Specification & Placement

  • File Included: includes/patient_form_prev_report.php
  • Container: <div id="history_report_section" class="container-fluid pt-4 px-4">
  • Section Title: History report with dynamic count badge and patient full name summary.
  • Purpose: Automatically scans and displays all past cases sharing the exact same patient first name (pname) and last name (plastname), excluding the active case itself.

B. Key Capabilities & Privacy

  • Direct SN Links: Surgical numbers are rendered as links to patient_edit.php?id={id} with target="_blank", allowing pathologists and staff to examine prior history in a new tab without navigating away or losing unsaved edits.
  • Previous Report Badge: In the วันที่รับเข้า column, if a case's intake date is earlier than the currently opened report (date_1000 < current date_1000), it displays a blue previous report badge (badge bg-primary).
  • Batch Diagnosis Extraction: Efficiently extracts the latest Pathological Diagnosis (or group 2) snippet from presultupdate for all matched cases.
  • Customer Isolation: Customer accounts (groups 5000 / 5100) are strictly scoped to cases from their own hospital (phospital_id = $_SESSION['user']->uhospital_id), preserving hospital patient confidentiality.
  • Columns Displayed: #, Surgical Number (SN), วันที่รับเข้า (with previous report badge), วันที่ออกผล, โรงพยาบาล / HN, พยาธิแพทย์, ผลการวินิจฉัย (Diagnosis Preview), สถานะ (Status), and เปิดดู (Action Button).
